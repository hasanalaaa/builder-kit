# Design tokens

Tokens are named design decisions. Code consumes names, never raw values, so one edit restyles everything and AI agents can't invent a 14th gray.

## 1. Three tiers

| Tier | Example | Who uses it |
|------|---------|-------------|
| Primitive (raw scale) | `--blue-600: oklch(0.55 0.19 255)` · `--space-4: 1rem` | Only semantic tokens |
| Semantic (meaning) | `--color-bg`, `--color-fg`, `--color-fg-muted`, `--color-primary`, `--color-primary-fg`, `--color-border`, `--color-danger` | All components |
| Component (optional) | `--button-height-md`, `--card-padding` | One component, when it needs a knob |

Rules:
- Components reference semantic tokens only. A component that uses `--blue-600` directly breaks dark mode and theming.
- Name by role, not appearance: `--color-danger`, not `--color-red`.
- Every background token has a matching foreground token (`--color-primary` / `--color-primary-fg`). `contrast.py --tokens` checks these pairs.

## 2. Standard semantic set (shadcn-compatible names)

```
background / foreground            page
card / card-foreground             raised surfaces
popover / popover-foreground       menus, popovers
primary / primary-foreground       main action, brand moment
secondary / secondary-foreground   secondary action
muted / muted-foreground           quiet surfaces, secondary text
accent / accent-foreground         hover/selected surfaces
destructive / destructive-foreground
success / success-foreground
warning / warning-foreground
info / info-foreground
border, input, ring                lines, field borders, focus ring
chart-1 … chart-5                  data series (color.md §7)
```

`palette.py` generates exactly this set for light and dark.

## 3. Scales

**Spacing** (4px base; use the step names, not px):
`0, 1=4, 2=8, 3=12, 4=16, 5=20, 6=24, 8=32, 10=40, 12=48, 16=64, 20=80, 24=96, 32=128`
Tailwind's default spacing already follows this. Arbitrary values (`p-[13px]`) are a lint warning.

**Type** (see `typography.md`): `xs 12, sm 14, base 16, lg 18, xl 20, 2xl 24, 3xl 30, 4xl 36, 5xl 48, 6xl 60, 7xl 72` for a product UI; marketing display uses fluid `clamp()` steps.

**Radius**: pick a personality and stick to it.
| Personality | sm | md | lg | full |
|-------------|----|----|----|------|
| Sharp / technical | 2 | 4 | 6 | 9999 |
| Neutral | 4 | 8 | 12 | 9999 |
| Soft / friendly | 8 | 12 | 20 | 9999 |
Nested radius rule: inner radius = outer radius − padding (never larger than the outer).

**Elevation** (shadows have offset + blur; colored zero-offset halos are not elevation):
```
--shadow-xs: 0 1px 2px oklch(0 0 0 / 0.06);
--shadow-sm: 0 1px 3px oklch(0 0 0 / 0.08), 0 1px 2px oklch(0 0 0 / 0.04);
--shadow-md: 0 4px 12px oklch(0 0 0 / 0.08), 0 2px 4px oklch(0 0 0 / 0.04);
--shadow-lg: 0 12px 32px oklch(0 0 0 / 0.12), 0 4px 8px oklch(0 0 0 / 0.04);
```
In dark mode, elevation comes from lighter surfaces (`card` lighter than `background`), not darker shadows.

**Z-index** (named layers; never 9999):
```
--z-base: 0; --z-raised: 10; --z-dropdown: 1000; --z-sticky: 1100; --z-overlay: 1200;
--z-modal: 1300; --z-popover: 1400; --z-toast: 1500; --z-tooltip: 1600;
```

**Motion** (see `motion.md`):
```
--duration-instant: 100ms; --duration-fast: 150ms; --duration-base: 220ms; --duration-slow: 320ms; --duration-slower: 480ms;
--ease-out: cubic-bezier(0.16, 1, 0.3, 1);      /* entrances, most UI */
--ease-in-out: cubic-bezier(0.65, 0, 0.35, 1);  /* moves between two on-screen states */
--ease-in: cubic-bezier(0.7, 0, 0.84, 0);       /* exits */
```

**Breakpoints**: `sm 640, md 768, lg 1024, xl 1280, 2xl 1536`. Prefer container queries for components.

**Density**: comfortable by default; compact for data-dense tools via a `data-density="compact"` attribute that reduces control heights (40→32), paddings and font size by one step.

**Control heights**: `sm 32, md 40, lg 48`; touch targets ≥ 44pt on mobile even when the visual is smaller (padding or hit-slop).

## 4. Implementation

### CSS variables (any stack)
```css
:root {
  --color-background: oklch(0.99 0.003 255);
  --color-foreground: oklch(0.21 0.02 255);
  /* … generated by palette.py … */
  --radius-md: 0.5rem;
}
.dark, [data-theme="dark"] { /* dark overrides */ }
@media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) { /* dark overrides */ } }
```

### Tailwind v4 (`@theme` in CSS)
```css
@import "tailwindcss";
@theme {
  --color-background: oklch(0.99 0.003 255);
  --color-primary: oklch(0.55 0.19 255);
  --font-sans: "Inter", "IBM Plex Sans Arabic", system-ui, sans-serif;
  --radius-md: 0.5rem;
}
@custom-variant dark (&:where(.dark, .dark *));
```
`palette.py --format tailwind` prints this block.

### shadcn/ui
Uses `--background`, `--foreground`, `--primary`… without the `color-` prefix. `palette.py --format shadcn` prints that mapping.

### React Native / Expo
Export tokens as a typed TS object (`palette.py --format json` → `tokens.ts`), use `useColorScheme()` for light/dark, and a `StyleSheet` or NativeWind with the same names.

### SwiftUI / Compose
Asset catalog colors with Any/Dark appearances named after semantic tokens; Compose `ColorScheme` roles mapped from the same JSON.

## 5. Theming and dark mode rules

- Dark mode is a second set of semantic values, not `filter: invert`.
- Dark backgrounds are near-black with a slight tint of the brand hue (L ≈ 0.14–0.20), not pure `#000` (except OLED-first media apps).
- Reduce saturation of large colored surfaces in dark mode; keep accents bright enough for 3:1 against the surface.
- Respect `prefers-color-scheme`, let the user override, persist the choice, and set `color-scheme: light dark` so form controls and scrollbars follow.
- Images: provide dark variants for logos/illustrations that disappear on dark.

## 6. Governance

- Tokens live in one file; `DESIGN.md` documents them.
- New token only when two components need the same new value. One-off values are a smell.
- `design_lint.py` warns on raw hex/rgb/hsl in component files and arbitrary Tailwind values; fix by mapping to a token.
